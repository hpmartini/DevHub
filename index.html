Terminal first. Editor and browser built in.

Agents are not hidden behind a chat box. Every session is a real terminal running the unmodified claude CLI — and the tools you need around it live in the same window.

  • Terminal first

    Each agent is a real terminal (claude attach), not a re-rendered transcript. Type, scroll, interrupt — exactly like in your shell. Plain terminal tabs sit right next to them.

  • VS Code embedded

    code-server opens on the project or on the agent’s worktree, with your extensions, git and debugger.

  • Browser embedded

    Preview the app an agent is building at desktop, tablet or phone width, with console and network logs beside it. Links from a session open in a pane next to it.

Your CLI, your machine, your rules.

The unmodified claude CLI
DevOrbit drives the CLI you already have. It does not patch it, wrap it or read tokens out of it.
Runs on your machine
Your code, your keys, your network. Nothing is sent to a server we run.
Scoped to your projects
Sessions can only be dispatched into the project folders you configured. Symlinks are resolved before the check.
Unsafe flags locked
Flags that widen a session’s reach — --dangerously-skip-permissions, custom settings, MCP configs — are refused unless you allow them.

Questions worth asking.

Do I need an API key?

No. DevOrbit drives the claude CLI you are already signed in with and uses that subscription — no second key, no token scraping.

Which agents does it work with?

Agents are Claude Code sessions. The usage page additionally reads local logs of Codex accounts and MiniMax, so you see all your token use in one place.

Does DevOrbit change the claude CLI?

No. It uses the unmodified CLI and the state it already keeps in your home directory. Nothing is patched, wrapped or bypassed.

Does it run in the cloud?

No. Dashboard, database and terminals run on your machine; agents on other machines stay there and join through your tailnet.

Does it work on Windows?

No native Windows build yet. macOS and Linux are supported; on Windows, run it in WSL.

What is Pro?

The live workflow visualisation is planned for a Pro version. Everything else on this page is in the open-source pre-release today.
